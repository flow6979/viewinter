**Ek line:** DP = recursion + caching; choices aur repeat hote subproblems ke saath "min/max/count/possible" pehchaano, phir state, transition, base case aur order define karo.

- **Cues:** optimum, number of ways, "can you", greedy ka counter-example, n ≤ 5000 ya do strings ≤ 1000.
- **4 steps:** state words me → har choice ka transition → base case → fill order (ya memo).
- **Memo vs table:** memo jaldi likhta hai; table deep recursion se bachata hai aur rolling arrays deta hai.
- **1D:** climbing stairs, house robber: `dp[i] = max(dp[i-1], dp[i-2] + a[i])`.
- **0/1 knapsack:** capacity neeche ki taraf loop; subset sum / partition iska bool version.
- **Unbounded (coin change):** capacity upar ki taraf; coins outer = combinations, coins inner = permutations.
- **LIS:** `tails` + `lower_bound`, O(n log n).
- **LCS / edit distance:** prefixes pe `dp[i][j]`, O(n·m).
- **Interval DP:** `dp[l][r]`, har split k try, length ke order me bharo, O(n³) (burst balloons, MCM).
- **Bitmask / digit DP:** n ≤ 20 → `dp[mask][i]`; 1e18 tak digit rules → (pos, tight, …).

**Interview me bolo:** "dp[i][j] = … maano; har step pe take ya skip, to dp[i][j] = … ; base case …; complexity O(states × transitions)."

**Galti mat karna:** Memo me 0 ko "not computed" marker rakhna, aur counts pe `int` overflow (`long long` ya mod 1e9+7 lo).
