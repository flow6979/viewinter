**In one line:** DP = recursion + caching; spot "min/max/count/possible" with choices and repeated subproblems, then define state, transition, base case and order.

- **Cues:** optimum, number of ways, "can you", greedy has a counter-example, n ≤ 5000 or two strings ≤ 1000.
- **4 steps:** state in words → transition per choice → base case → fill order (or memo).
- **Memo vs table:** memo is quicker to write; table avoids deep recursion and allows rolling arrays.
- **1D:** climbing stairs, house robber: `dp[i] = max(dp[i-1], dp[i-2] + a[i])`.
- **0/1 knapsack:** loop capacity downward; subset sum / partition is the bool version.
- **Unbounded (coin change):** loop capacity upward; coins outer = combinations, coins inner = permutations.
- **LIS:** `tails` + `lower_bound`, O(n log n).
- **LCS / edit distance:** `dp[i][j]` on prefixes, O(n·m).
- **Interval DP:** `dp[l][r]`, try every split k, fill by length, O(n³) (burst balloons, MCM).
- **Bitmask / digit DP:** n ≤ 20 → `dp[mask][i]`; digit rules up to 1e18 → (pos, tight, …).

**Say in the interview:** "Let dp[i][j] be … ; at each step I either take or skip, so dp[i][j] = … ; base case …; that is O(states × transitions)."

**Avoid:** Using 0 as the "not computed" memo marker, and overflowing `int` on counts (use `long long` or mod 1e9+7).
